# 启动表情模板检查设计

## 目标

每次 NoneBot 启动时自动检查外部表情模板仓库，让使用者能从日志明确判断模板是否已存在、是否需要下载以及是否成功加载。检查与下载继续在后台执行，不阻塞机器人启动；内置表情始终可用。

## 当前问题

`MemeRepoManager` 已在启动钩子中调用 `kickoff()`，但 `_repo_ready()` 只检查模板目录非空，无法排除空壳目录或无效内容。下载过程只有开始与结束日志，没有逐仓库进度和最终汇总。

## 方案比较

- **完整检查与清晰日志（已选择）**：校验有效模板目录，输出逐仓库进度、模板数量、加载结果及最终汇总；缺失或无效时重新下载。后台运行，不增加启动等待。
- **实时下载进度条**：额外依赖镜像提供准确的 `Content-Length`，不同下载源表现不一致，暂不在本次引入。
- **启动等待全部完成**：结果最直接，但网络慢时会阻塞机器人启动，不符合现有非阻塞设计。

## 实现约定

- 每次启动仍由 `_check_meme_resources_on_startup()` 触发四个外部仓库的检查。
- 有效模板定义为仓库模板目录的直接子目录中存在 `__init__.py`；至少存在一个有效模板才视为仓库就绪。
- 已就绪的仓库不重复下载，记录 `检测到 N 个模板`；未就绪的仓库重新下载并在解压后重新校验。
- 每个仓库按 `[当前/总数]` 记录检测、必要时的下载、加载结果，成功后包含模板数量。
- 全部结束后输出可用仓库数；有失败项时记录失败仓库名称，不让单个仓库异常中断后续检查。
- 保持 `enabled=False`、缺少 backend 或未配置目录时的现有无操作行为。
- 更新 README 的启动检查说明，并补充有效目录、空壳目录重下、下载后校验和汇总日志相关测试。

## 非目标

- 不每次启动强制更新已有仓库。
- 不校验上游仓库是否发布了新版本。
- 不增加终端实时进度条，不阻塞启动。
